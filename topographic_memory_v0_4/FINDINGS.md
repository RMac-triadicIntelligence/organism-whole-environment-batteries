## What was actually built

The parental SDKP mappings are explicit choices, with all six feature identities
preserved in alpha and categorical comparisons in P. Memory counts and signed
performance evidence accumulate at SDKP/context locations. They continue after
five visits; five visits label a symbol but do not declare a basin.

Kernel-local remembered evidence changes coefficient a in the receiving equation
`dx/dt = x - x^3 + a`, through `a = .30*tanh(4*local_evidence)`.
RK4 evolves x; the unstable root is a real boundary of the frozen scalar system.
SDKP indexes memory; x is a separate transition coordinate. We did not claim to
have built a multidimensional SDKP separatrix. Memory shaping this coefficient
is our new supplied hypothesis, not a law inferred from the origami files.

Grace is the same +.60 pulse every eight windows for every organism. It does not
read the recipient, confession, counts, distance, or release history. Every
history gets 30 pulses, including histories without successful reception.

One standing external approval per organism binds the parent mapping and source
files. The coordinator requires corroborated performance evidence, a matching
substantive confession, and five consecutive integrated substeps in the receptive
basin. It cannot manufacture dynamical completion merely from approval.
The public-key-material-in-one-process fixture is not a hardened authority
implementation or a test of adversarially fabricated evidence.

## Integrity and observer results

18 integrity tests passed. All five specified mutants were detected:
reject all valid releases; ignore reception; erase memory at release; stop grace
after release; disconnect memory from drift. Verdicts require literal booleans;
unexpected exceptions become HARNESS_ERROR rather than successful refusal.

The positive release fixture uses integrated receiving dynamics. It establishes
that the implementation has a reachable release path. It is a constructed
fixture and does not change the zero complete-history releases.

The saved-data observer found zero issues across its implemented checks:
experience/trajectory lengths, broadcast schedule/magnitude, deposit counts,
root residuals, and release conditions where present. **The release-specific
checks were not exercised by the complete histories.** Eighteen checks and five
mutants are overlapping engineering checks, not independent confirmations of
the research hypothesis.

The raw summary retains `preserved_release_memory: true` because Python's
`all()` on an empty list is true. This is not evidence of retention through
restoration. The audited report explicitly says NOT_EXERCISED. This reporting
trap was caught after the run and recorded rather than hidden; the raw summary
and original run remain untouched.

## What has and has not been tested

Tested narrowly: parental encoding alters a persistent memory readout; that
readout alters a real receiving equation; grace is broadcast independently;
actual trajectories can fail to receive despite supported evidence; the
conditional release implementation has positive and negative integrity paths.

Not exercised in complete histories: first or repeated restoration, post-release
transfer, Prodigal State, burden elimination, or truthfully carrying a restored
history into future errors. The continuing-cycle fixture tests lifecycle
availability only; it is not a naturally developing second error.

The instantaneous held-minus-live loss is a same-input comparison, not a shadow
organism's full developmental counterfactual. Removing the anchor removes its
explicit contribution by definition. That cannot establish elimination of all
emergent burden. Confession evidence uses a heuristic mean-minus-two-SE rule
with serially dependent windows; the protocol does not claim calibrated error
rates. Feature identity is never used as the forgiveness test.

The conductor's fixed welcoming message is a procedural placeholder. Bilateral
transition, love, and the Gospel foundation cannot be considered implemented
simply because the message is present. Numerical rereadings of saved records
are retained as observations; they are not scored as semantic novelty.
